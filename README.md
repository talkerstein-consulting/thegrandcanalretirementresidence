# Grand Canal — static reproduction of www.grandcanal.ca

A 1:1 static copy of the current Wix site (desktop **and** Wix's separate phone layout),
with two permitted changes: faster loading, and every visible phone number is a
tap-to-call link. See [AUDIT.md](AUDIT.md) for the reference audit, measured results,
and the known gaps.

## Run it locally

```bash
npm install
npm run serve
```

Open http://localhost:4321. Phones (by user agent) get the mobile layout at the same URL,
like Wix does. To see the phone layout on a desktop, use Chrome DevTools device mode
with an iPhone/Android profile and reload, or open `/m/` URLs directly.

## How it is made

| Step | Command | What it does |
|---|---|---|
| Capture | `npm run capture` | Renders every route on the live site in Chrome (desktop at 1920px + iPhone), lets Wix finish rendering, snapshots slideshows / the open mobile menu, removes the Wix runtime and saves the frozen DOM to `.cache/capture/`. Trackers are blocked so the crawl never hits the client's analytics or call tracking. |
| Build | `npm run build` | Turns the captures into `public/`: self-hosts images (WebP at the exact crops Wix used, plus wider same-crop sizes for full-width photos), open-licence fonts, CSS, PDFs and the video; lazy-loads below-the-fold images; rewrites links; links phone numbers; re-injects the site's tracking embeds (`tools/embeds.json`) on the same pages as on Wix; writes `vercel.json`, `sitemap.xml`, `robots.txt`. |
| Check | `npm run check` | Screenshots every page and compares it with the live-site reference screenshots (pixel diff, height, horizontal overflow, console errors, broken requests). |
| Test | `npm test` | Exercises the interactions: slideshow, mobile menu, gallery viewer and arrows, services gallery, video, forms, `/review` redirect, every internal link and asset. |

`src/site.js` (15 KB, 4.7 KB gzipped) replaces the ~0.8–0.95 MB of Wix JavaScript each
page loaded, for the few interactions the pages actually use. `src/site.css` holds the only CSS additions.

Re-run `capture` only when the live site changes; `build` works offline from the cache.
Content and layout come from the capture: do not hand-edit `public/`; for the visual
pass, edit the captured pages or move to a source format first.

## Redesign (clean templates)

The homepage is now rebuilt from clean templates in `src/clean/` (real header/section/footer
structure, one container grid, spacing and type-scale tokens in `styles.css`). `npm run build`
runs `tools/build-clean.mjs` after the Wix build; it replaces the captured page at the same route
for desktop and phones, re-adds the tracking embeds, and keeps the captured Wix homepage at
`/legacy`. A black bar pinned to the bottom of both homepages switches between them for review.
The other pages are still the 1:1 Wix copy.

## Layout

```
public/            deployable site (desktop pages at the root, phone layout under /m/)
src/site.js|css    behaviour/CSS that replaces the Wix runtime
tools/             capture, build, serve, check, test scripts; routes + tracking embeds
.cache/capture/    frozen DOM of every page (build input, committed)
```

## Deploying (Vercel, static)

`vercel.json` is generated by the build. It serves `public/` as-is: no build step, no
functions, no image optimisation, no storage. Phones are routed to `/m/...` by user agent
before the static file match (Wix-style dynamic serving, with `Vary: User-Agent`),
`/review` keeps its 301 to the Google review form, and `/assets/*` is cached immutably.
Nothing has been deployed.

Before going live, see "Before launch" in AUDIT.md (form backend, font licences).
